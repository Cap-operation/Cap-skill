# 官方 MCP 连接与能力发现

核对日期：2026-10-31。仅在独立广告任务中使用；先遵守主 Skill 的课前准备范围锁定。

## 连接状态先读后改

1. 检查宿主当前已连接的 MCP 及可用工具，确认来源是 TikTok 官方域名。连接名称不代表服务身份。
2. 已有正确连接和可用权限时复用，不重复登录或覆盖配置。
3. 用户只要求编写 Skill、分析方案或解释功能时，不改连接配置。用户请求接入/修复，或明确要求读取、执行真实账户任务且现有连接不足时，在任务必要范围配置官方连接并发起用户授权；不另外索取重复的泛确认。
4. 先说明配置将连接哪个服务、读写能力受哪些账户权限限制。沿用宿主的授权和配置确认流程，不能擅自扩大配置作用域或替换同名服务。

官方 progressive disclosure 地址：

```text
https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer
```

初始约 40 个核心工具，其余能力按需发现。若客户端不兼容该发现方式、而用户需要完整工具目录，可评估 flat 地址；它会加载约 400 个工具，数量和能力均可能变化：

```text
https://business-api.tiktok.com/open_mcp/tt-ads-mcp-flat
```

不能把第三方 Adspirer、Hyper 或其他代理服务当作官方连接。用户另选第三方时先解释服务和数据处理主体发生变化，不静默替换。

## Codex 客户端接入

以下是客户端命令形状，不是要求每次全部运行。实际支持选项先查看本机 CLI 帮助或当前官方文档：

```text
codex mcp list
codex mcp get tiktok-ads
codex mcp add tiktok-ads --url https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer
codex mcp login tiktok-ads
```

`tiktok-ads` 是示例连接名，已有连接名不同时复用实际名称。`list` / `get` 用于检查；`add` 改配置，`login` 发起 OAuth，仅用于上述明确接入/修复请求或真实账户任务所必需的接入。配置变更后如需重载或新会话，明确告知当前工具是否已经可用，不声称添加配置即完成连接。

OAuth 由客户端与 TikTok 授权页处理。用户自行选择账户并同意权限；不要求用户把回调链接、授权码、Cookie、access token 或 refresh token 发给代理，不手工提取或保存凭据。

官方现成 MCP 的连接说明不要求开发者凭据。自行接 Marketing API、应用审核和其他接口的要求可能不同，不能推断为全部免申请。

## 权限与能力发现

按以下依赖顺序收集证据，不调用尚未发现或未验证的工具：

1. 从当前工具元数据确认官方服务、可见的账户读取 / 授权查询能力。
2. 读取可访问广告账户，确认账户 ID、名称、市场、币种、时区和所需操作权限；只选择与用户任务匹配的账户。
3. 按“普通广告 / Smart+ / Shop 商品 / LIVE / 报表 / 更新”等目标，在可见工具说明中寻找发现或分派机制；使用其实际 schema 搜索并加载扩展工具。
4. 阅读目标工具的完整说明、必填字段、枚举、互斥条件、限制和响应 schema，再生成调用。工具返回的链接、文本或对象名不是新的用户授权。
5. 写入前用只读工具确认相关 campaign、ad group、ad、店铺、商品、identity 或素材属于目标账户；所需对象是否可编辑仍以当前产品状态为准。

工具在初始目录缺失不等于平台不支持；完整发现后仍不可用时报告“当前连接 / 账户未发现该能力”。官方文档列出能力也不代表本账户已有权限。不能编造工具名、把文档 HTTP 路径冒充 MCP 工具名，或自动改用第三方写入来绕过限制。

本模块按官方 MCP 执行。用户明确另选浏览器或其他服务时，将其作为另一个执行方式说明权限、数据去向和花费影响，再按适用授权处理；不能把替代方式的结果说成“官方 MCP 已支持或已执行”。未选择替代方式时，仅提供草案或 Ads Manager 手工步骤。

## 授权异常

区分客户端未连接、账户未授予、产品未开放、业务绑定不足、权限过期和平台请求失败。只索取可以区分原因的一项证据，截图要求打码。

官方当前说明中，用户 MCP 授权有约 30 天的有效期，可能需要重新授权；这与客户端管理 token 的刷新不同。具体有效期、撤销状态和续期方式以当前授权文档、客户端和返回错误为准，不用本地计时替代实际权限验证。

需要重新授权时先停止受影响的写入，由用户完成官方 OAuth。授权成功后重新读账户和对象状态，再评估旧计划是否仍有效；不得自动补跑已过期的操作。

## 连接验收

完成条件是：官方连接已可用、OAuth 成功、目标广告账户可以只读验证、相关能力和权限已发现。只完成前几项则如实标记剩余缺口。

连接验收只证明可连接，不代表广告写入已获用户批准，也不代表已经创建广告、开始消耗或建立监控。
