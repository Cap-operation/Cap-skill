# TikTok Shop Product / LIVE GMV Max

核对日期：2026-10-31。平台和工具行为会变化；以下是官方文档核对点，不是固定 HTTP 调用模板。先发现当前 MCP 工具并读完整 schema，再决定实际字段、枚举和流程。

## 产品与资格

先区分 Product GMV Max、LIVE GMV Max、普通 Shop Ads 和 Smart+，不要仅因名称含 Shop 就混用创建或报表工具。官方目录或文档支持 GMV Max，不保证当前账户、市场、店铺或 identity 已开放写入能力。

沿用 `../../cap-tiktok-shop/references/paid-growth.md` 的商品、素材和库存履约前置条件，利润按 `../../cap-skill/references/profit.md`；这是课程投放方法。保本 ROAS 只对应普通广告付费归因，不能直接当 GMV Max ROI 目标。账户与产品资格必须从当前官方工具读取，不用课程完成状态替代。

当前官方 GMV Max 创建文档的典型检查点如下；仅在相应字段存在且适用于当前操作时使用：

- 店铺列表中的 `is_gmv_max_available` 应为真；检查目标店铺与 advertiser 绑定关系。
- `exclusive_authorized_advertiser_info.advertiser_id` 应匹配目标 advertiser。修改 GMV Max 独占授权会影响其他账户，属于独立写入，不能作为“只读预检”静默执行。
- 全店推广能力按当前 `shop_ad_usage_check` 结果判断；指定商品检查 GMV Max eligibility、可售和占用情况，不硬编码“ALL”一定可用。
- LIVE 检查当前 identity 的 `live_gmv_max_available`、直播和店铺关系、排期及商品准备。不能把普通视频 identity 权限推定为 LIVE GMV Max 权限。

资格不满足时给出具体阻塞和最小处理步骤，不自动切换广告账户、抢占商品、终止冲突计划或改独占授权。

## 创建不等于暂停草稿

当前官方 create 文档不提供通用的 `operation_status` 创建参数，Product / LIVE 示例返回 `operation_status=ENABLE`。这意味着不能承诺 GMV Max 可以先以暂停状态创建。

创建前必须查清当前工具说明中的立即投放行为。无法确认非投放状态时，将本次创建视为可能开投：向用户展示账户、店铺 / identity、商品范围、预算与目标、时段和可能立即消耗的结果。只有已有批准明确覆盖开投和额度才调用；否则只形成文本草案。

不要自行添加普通广告的 paused 枚举，不把未来开始时间当成万能暂停方案。当前工具若支持安全的非投放状态，也先核对其实际语义和对该 GMV Max 产品的适用性。

## 预算与自动放大

逐项核对日预算 / 总额的产品语义、ROI 目标、最大预算、有效期和跨午夜花费；日预算不能直接等同整个授权期的总消耗上限。

当前文档可能出现新 `auto_budget` 与旧 `auto_budget_enabled`。按实时 schema 选择，不同时照抄两套字段。默认不申请自动放大预算；如果支持显式关闭，使用当前 schema 的关闭方式并回读。不能因不传字段就断言默认已关闭。

创建前若无法核实自动增额已关闭，且本次未获对应专项授权，止于文本草案；不能先开投，再靠创建后回读弥补这一授权缺口。

促销日 `promotion_days` 有特别风险：当前官方说明表示传入该对象即自动启用 `is_enabled`，不能通过传 `false` 来保证关闭。未获专项批准时省略整个对象，并在回读中核对实际设置。平台规则更新后以当前说明为准。

启用上述功能必须取得用户对自动增额的专项授权，核对 `maximum_budget` 或当前等价字段的约束语义、适用日期及整个授权期的最坏花费。字段名含“maximum”不代表天然覆盖全部产品、全部日期或全部账户；无法验证总风险时不自动启用。

降低 ROI 目标可能增加消耗并改变利润，视为需要授权范围覆盖的调整。不得为了花出预算无限下调目标，也不虚构某个统一 ROI 或日预算下限。

## Product 工作流

1. 读取店铺、授权广告账户、可用产品范围、已有 GMV Max 计划和素材授权，检查商品占用及冲突。
2. 确认单品 / 多品 / 全店等当前可用范围、预算、ROI 目标、开始与结束规则以及素材资格；只有当前 schema 支持时才提供对应选项。
3. 给出包含开投后果和预算上限的计划，检查批准后创建或更新。
4. 回读对象、状态、商品范围、预算、目标、排期和自动增额设置；读取结果与获批计划不一致时停止后续写入并报告。
5. 按统一指标口径观察；只在用户批准的规则内更改，不把自然 GMV 增长直接认作广告净增量。

## LIVE 工作流

1. 读取 identity / 店铺资格、直播对象、当前计划与场次，核对用户要处理的直播和时区。
2. 确认直播准备、商品库存、投放时段、预算和当前工具支持的目标；不在用户没有直播计划时自动建场次或启动直播。
3. 区分“创建广告计划”“管理场次”“开始直播”“开启投流”四种操作，按各自 schema 和授权执行，不能合并成含糊的“开始”。
4. 回读计划与场次关系、预算和状态；直播已结束或排期已变时停止原执行计划并重新评估。
5. 不同场次的收入、花费、时长和自然流量分开比较，避免把跨场延迟归因算到错误场次。

## 时间、重试与报表

当前 GMV Max create 文档的 `schedule_start_time` 按 UTC+0；用户提供本地时间时先用明确时区转换，并在批准计划中同时显示账户当地时间与平台要求的时间。其他字段不得据此一概推断为 UTC，逐项查看说明。

当前 create 文档对 `request_id` 的幂等缓存约为 10 秒；相同 ID 超过窗口仍可能新建对象。不能把它当永久去重机制。超时后先查询计划、返回 ID、对象关系和已保存配置；无法唯一确认时停止重试，请用户核对。详见 [执行授权与恢复](authorization-recovery.md)。

GMV Max ROI / 总 GMV 的自然、付费、达人和商品覆盖范围以对应产品当前官方报表定义为准；不能直接标为普通广告付费 ROAS 或净利润。报表必须带产品、日期、时区、归因和数据延迟说明，按 [分析与优化](analysis-optimization.md) 处理。
