# 订单、客服、售后与持续运营

核对日期：2026-09-17。用于商品开始出单后的日常运营、异常处理、复盘和放大。发货、取消、退货、退款、客服和绩效时限按目标市场当前政策执行，不跨市场套用固定天数。

## 每日优先级

1. 处理违规、冻结、商品下架和平台待办；
2. 处理待发货、物流异常、缺货和可能超时订单；
3. 处理退款、退货、差评和客服消息；
4. 检查库存、价格、优惠和商品状态；
5. 推进内容、达人、广告和直播；
6. 复盘数据，确定第二天动作。

先保护店铺健康和真实利润，再追 GMV。

## 订单与发货

- 每天检查待处理、待发货、运输中、异常和取消订单；
- 按后台要求在时限内打印面单、交接并取得有效物流扫描；
- 发货前核对 SKU、数量、质量、配件、包装和面单；
- 缺货时立即停止对应库存和推广，按平台流程处理订单；
- 不上传虚假单号，不提前点发货，不用空包或错误物流制造履约；
- 记录延迟、丢件、破损和错误发货原因，向仓库追责并修流程。

多仓运营要核对库存同步、订单路由和退货地址。可售天数低于补货周期时，及时降推广或补货。

## 客服

按“确认问题 → 给明确方案 → 按时完成 → 留下记录”处理。优先回答尺寸、适配、使用方法、物流、缺件和退换货。

- 使用买家语言，短句回复；
- 不承诺无法控制的到货时间或结果；
- 不要求买家撤销合理投诉、修改真实评价或转到站外解决；
- 不索取不必要的身份证、支付信息和验证码；
- 同类问题重复出现时，改商品卡、包装说明或质检。

### 卖家中心原生客服设置

TikTok Shop 卖家中心自带的客服功能归本篇；要接 Chatwoot 等第三方客服系统、多平台统一收消息时，才交给 [客服大师](../../cap-tiktok-service/SKILL.md)。下面四项的入口名称、可设内容和考核口径都需核对当前后台，界面按用户发来的截图说，不编菜单名：

- **自动回复**：买家首次进线和非工作时间的回复，写清多久内会有人回、常见问题去哪看；
- **快捷回复**：把尺寸、物流时效、退换货、使用方法等高频问题各写一条；
- **常见问题**：后台支持时，把高频问答放进商品或店铺的常见问题；
- **消息响应时效**：平台可能把回复速度计入店铺表现，按后台显示的要求安排值班。

文字由 AI 起草，用目标市场语言写并附中文对照（见[共用交接约定第 10 节](../../cap-skill/references/shared-contracts.md#10-交付语言)）。自动回复会直接发给买家：先给用户看全文，用户确认后由用户自己在后台开启，AI 不代为上线。

## 取消、退货和退款

先读取订单所在市场的当前页面和倒计时：

1. 确认请求类型、原因、证据和处理时限；
2. 对照商品描述、物流轨迹、质检和开箱资料；
3. 在后台允许的操作内接受、拒绝、退款或申诉；
4. 需要退货时使用平台认可地址和流程；
5. 处理后记录根因和损失；
6. 同一原因多次出现时停止新增推广；正在运行的广告只在已有应急暂停授权内暂停，否则提醒用户自行暂停（广告可能仍在消耗），再修产品、页面或履约。

不把其他国家的退货天数写成统一规则。自动同意、退款不退货、争议和举证规则按当前订单页面执行。

中国直发的跨境订单：退货怎么处理以平台当期规则为准。常见情况是只退款不退货，或者退回来的运费比货还贵；算利润时，退款订单按全损算（货款、运费都收不回），需核对当前规则。

## 评价与店铺健康

卖家中心的违规、扣分、商品下架和店铺冻结都在本篇处理；TikTok 账号功能受限、视频 0 播放交回总入口（运营诊断）。

每日查看商品违规和知识产权通知、延迟发货、商家取消、物流异常、退款退货、差评、客服工单、质量问题和店铺权益限制。

收到违规时先保存原文、商品、订单和截止时间，再按证据整改或申诉。不删除问题后原样重上，不通过换词、换图或换类目规避审核。

## 数据复盘

### 每日看异常

检查流量、点击、加购、成交、广告花费、退款、待发货、缺货和违规。当天只处理明显异常和紧急履约，不因一小时波动反复改策略。

### 每周看漏斗与利润

按商品、内容、达人、广告和直播拆分：曝光、观看、商品点击、加购、成交、客单、采购、物流、平台费用、达人佣金、优惠、广告、取消、退款、差评、净收入、贡献利润、库存周转和断货风险。

用贡献利润（按 [profit.md](../../cap-skill/references/profit.md)）和可持续履约判断，不用 GMV 代替利润。

复盘完，用户同意时把本周的 SKU 表现（跑出来、亏钱、退款高的原因）追加到[商家档案](../../cap-skill/references/shared-contracts.md#8-商家档案本地)的 `回流.md`，实测有变化的成本更新到 `成本.csv`；写之前一句话说明要记什么，用户说“别记”就不记。

### 每月做商品分层

- 放大：贡献利润为正、低售后、素材和供应可复制；
- 优化：有需求，但商品卡、价格、内容或履约存在一个明确短板；
- 观察：数据不足，继续小规模测试；
- 淘汰：贡献利润持续为负、高退款、高违规或供应不稳定。

每个商品只确定一个主要动作：加预算、补素材、改页面、改价格、补货、降库存或下架。不要同时大改所有变量。

## 开店后很久没出单（0 单诊断）

商品上线后很久没有订单时用这一节，不先去投流。本节例外：一次列出下面 3 张截图（先把账号、手机号、买家信息打码），页面名称以当前后台为准：

1. 商品列表里这个商品的状态（是否在售、有没有待补资料或违规提示）；
2. 数据罗盘里这个商品的漏斗数据（曝光、点击、加购、成交），选近 7 天或近 28 天；
3. 挂这个商品的内容数据（视频播放量和商品点击）。

商品状态不正常，先按商品上线和评价与店铺健康修好，再看漏斗。状态正常时，从上往下找第一个断掉的地方，每档只做一个动作：

| 卡在哪 | 先看什么 | 只做这一个动作 |
|---|---|---|
| 几乎没有曝光 | 有没有发内容挂这个商品、有没有达人在带 | 每天发自营内容挂商品，或开公开达人合作 |
| 有曝光、没点击 | 主图第一张、标题、价格，视频开头和商品是否对得上 | 换主图第一张或视频开头角度（钩子交拆解大师） |
| 有点击、没加购 | 商品卡、到手价、运费、评价 | 改商品卡和报价 |
| 有加购、没成交 | 优惠、到手价、运费、库存、送达时间 | 查结账条件，把下单前看到的总价和时效讲清楚 |

改完观察几天再看下一档，一次只改一样。视频本身 0 播放属于账号问题，交回总入口（运营诊断）。

## 持续增长循环

1. 从客服、评价、搜索词和评论提取新需求；
2. 优化商品卡、包装、说明和产品；
3. 把有效素材角度扩成自营内容和达人 brief；
4. 复投能带来正贡献利润的达人和素材；
5. 用 GMV Max 和直播逐步放大；
6. 增加套装、规格、关联商品和复购；
7. 根据贡献利润和库存决定扩品、扩仓或扩市场：扩品、扩达人、扩预算回到第 6 阶段（含第 7、10 阶段核对），扩市场回到第 0 阶段；
8. 重新进入“选品 → 上线 → 冷启动 → 放大 → 履约 → 复盘”循环。

扩国家前重新核对当地准入、税务、商品合规、物流、退货、结算和语言，不复制原市场设置直接开卖。

## 故障短版

> 目前判断：
> 影响订单：
> 截止时间：
> 现在只做：
> 完成标准：
> 如果失败：

规则说明仍使用 3–4 条短句；只有真实订单异常才使用这套字段。
