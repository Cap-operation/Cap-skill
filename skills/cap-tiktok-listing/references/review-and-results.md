# 审阅单与结果报告

字段为 Cap 内部交接约定，可用表格或 JSON 保存于用户允许的私有工作区；不含密码、Cookie、令牌。示例值均为虚构。

## 一、审阅单（推送或其他外部写入前）

纯文本资料包不需要审阅单。涉及导入、规则更新、推送、删除时填写，只列与本次动作相关的行。

```text
任务：DEMO-01 / 美国 / USD / America/Los_Angeles / 事实版本 facts-demo-v1（虚构）
动作：导入 | 更新规则 | 推送 | 删除导入项
执行路径：DSers → Shopify | DSers → Wix | TikTok 资料包（不执行）
```

| 区块 | 必填内容 |
|---|---|
| 对象 | 内部商品 ID；供应商商品/SKU；DSers 导入项 ID；拟推送变体清单（SKU、选项值、命中数量） |
| 目标店铺 | 平台、店铺真实 ID、显示名；多店时逐店列出；与上次批准相比是否变化 |
| 拟变更 | 标题/详情/图片前后对比；每个变体售价、划线价、成本、库存（标明草稿库存还是供应商库存）；定价来源（DSers 价或店铺定价规则）；可见性（仅后台 / 立即可售） |
| 副作用 | DSers 云端导入项创建或改写；规则重算可能覆盖后台人工改动；**推送可能修改账户物流配置**（列出当前值与可能变化）；配送模板可能回落默认；删除只影响导入列表 |
| 风险与拦截 | 上游价格/库存拦截原因；是否需要 `force_push`（需逐项写明风险与授权依据，布尔开关本身不是授权） |
| 利润 | 按共用利润口径的单件贡献利润或“成本未知” |
| 合规状态（来源、市场、事实版本） | 必填。TikTok Shop 路径引用店铺篇合规结论；独立站路径写用户或顾问提供的结论与来源。缺失时状态记“待补资料”，不推送 |
| 批准范围 | 已批准的账号、店铺、商品集合、动作、可见性、价格区间、允许的副作用、有效期、事实版本；本次超出部分 |
| 验证与停止 | 推送后回读哪些字段；出现超时、失败、warning 时停止什么 |

## 二、逐项结果报告

批次外层“成功”不代表每项成功。每个 商品 × 店铺 一行。

| 内部商品 | 导入项 ID | 店铺 ID | 动作 | 状态 | 验收层级 | warning | 证据 | 下一步 |
|---|---|---|---|---|---|---|---|---|
| SKU-DEMO-01 | IMP-DEMO-01 | SHOP-DEMO-01 | 推送 | 结果未知 | 已提交处理中 | 物流配置已启用（前：关；后：开） | 推送返回“已请求”后超时 | 到店铺后台核对，确认未生成再单项补推 |

**状态**（共用约定第 5 节原词）：草案 / 待补资料 / 准备好 / 已请求或处理中 / 已确认成功 / 部分成功 / 失败 / 结果未知 / 未执行 / 待验证。“部分成功”用于批次或多变体汇总，必须附逐项表。

**验收层级**（分开报告，不互相推断）：

1. 草稿完成：DSers 导入项存在，关键字段保存无失败 warning。
2. 已提交处理中：推送已请求，无终态。
3. 后台终态：目标店铺后台回读到商品与变体，或明确失败。
4. 前台可售：买家前台可打开、价格/库存/运费正确、可下单。

记录规则：

- warning 原文保留；“保存失败”类 warning 视为未保存。看不到 warning 不等于检查全部通过（输出可能截断）。
- job_status 只作上游本地记录，证据栏写明来源，不能单独支撑后台终态。
- 账户副作用记录前后值与时间。
- 删除导入项后写“导入项已删除；店铺商品未变更”，并标记该任务不可再推。
- TikTok 路径未执行时写“未执行：缺少 TikTok Shop 原生发布适配”，附资料包与转交的上线指导。
- 回填跨平台 ID 映射：平台、店铺、真实 ID、事实版本；同名商品不合并。
