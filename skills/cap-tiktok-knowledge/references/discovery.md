# 需求诊断与路线选择

在首次建库、已有库诊断或需求发生实质变化时读取。只解决影响当前下一步的未知项；下表是判断维度，不是一次性问卷。

## 对话节奏

- 先复用本轮对话、已确认方案和可访问的进度记录。用户给出长段背景时，提炼结论，不逐条重问。
- 每轮只问 1—3 个会改变下一步决定的问题；说明这些答案会影响什么。用户已经准备好资料时，可先检查一个样本，再追问。
- 用任务语言代替方法论测试。不要求新手先理解 PARA、MOC、原子笔记或向量检索。
- 用户说“帮我选”“先做简单版”时，给出有理由的默认方案并继续可逆工作；路径、资料授权、外传去向等必要信息仍须明确。
- 区分“用户已确认”“暂用默认”“尚未知”。沉默不等于同意，推荐也不等于已实施。
- 用户只想改视觉、导入一份资料或修复问题时，直接进入该路线，不重跑完整建库访谈。

## 起步与分流

| 当前情况 | 先做什么 | 本轮应得到什么 |
|---|---|---|
| 零基础、新建库 | 选一个近期真实任务，确认使用设备和目标位置 | 一个明确成果、可操作环境、最小起步路线 |
| 已有知识库 | 在指定范围内检查组织方式、代表性笔记、常用入口和当前痛点 | 保留项、问题项、最小调整建议 |
| 已有库、只改视觉 | 先看当前效果和喜欢的参考，检查平台与已有插件 | 要改的呈现层、参考效果、恢复方式 |
| 只导入资料 | 确认目标库和本批资料用途，抽查格式与质量 | 本批处理规则与小样本 |
| 团队使用 | 在目标之外补齐读写角色、内容责任人和访问边界 | 可实施的共享与维护方式 |
| 从上次继续 | 读取已保存进度，核对文件是否变化 | 当前阶段、已完成部分、下一动作 |

## 按需覆盖的维度

| 维度 | 要弄清的决定 | 何时追问或检查 |
|---|---|---|
| 真实用途 | 未来一周最希望完成的一件事；随后再扩展到三件 | 所有完整建库任务的起点 |
| 交付与验收 | 最先产出文章、决策依据、操作清单、课程笔记还是资料索引；怎样才算有用 | 目标仍停留在“管理资料”“提升效率”时 |
| 使用对象 | 个人、家庭、小团队或公司；谁阅读、谁编辑、谁维护 | 会影响共享、审核和内容划分时 |
| 现有基础 | 是否已有库、库位置、现有习惯、不能破坏的配置与内容 | 首次写入或整理旧库之前 |
| 资料组成 | Markdown、文档、网页、PDF、图片、录音、视频、聊天记录等；位置与大致体量 | 决定采样、转换工具和导入批次时 |
| 质量与来源 | 可否提取文字、是否有重复版本、是否可信、是否保留来源；语言与识别难点 | 查看代表样本后，避免仅凭扩展名判断 |
| 持续输入 | 以后从哪里新增、多久一次、谁处理、是否需要重复导入去重 | 建库方案准备进入长期使用时 |
| 设备与平台 | 电脑与手机系统、主要使用端、设备性能、公司插件限制 | 推荐插件、同步方式或大规模图谱之前 |
| 实际能力 | 当前是否能访问目标文件、操作 Obsidian、转写音频、识别图片或检索来源 | 对应动作发生前检查，不把写在说明里的能力当成现有工具 |
| 时间与费用 | 初次能投入多少时间、每周维护多久、可接受哪些付费服务 | 决定结构复杂度、处理范围和插件组合时 |
| 组织与浏览 | 经常按项目、主题、业务流程还是搜索找东西；是否需要主题索引 | 设计目录和入口之前；未知时提供简单默认 |
| 视觉与交互 | 偏好星空图谱、立体图谱、卡片地图、手绘白板或资料卡片；主要用来浏览、理解还是展示 | 读 visuals-and-plugins.md；用效果预览帮助选择 |
| 隐私与资料权限 | 哪些只能本地处理，哪些可以发给外部 AI；团队资料允许谁访问 | 转写、外部处理、同步或共享之前 |
| 同步与恢复 | 哪些设备要一致、当前用什么同步、是否有独立备份、能否恢复样本 | 正式批量导入或替换同步方案之前 |
| AI 问答 | 是否需要跨资料提问、答案是否须引用原文、是否限定本地运行 | 用户明确需要时再设计检索与问答层 |
| 更新与责任 | 哪些资料有有效期，谁能确认“现行版本”，谁处理冲突 | 操作手册、产品资料、政策等团队内容 |

补齐这些维度不要求每项都问用户。文件格式、插件、链接状态等可以在授权范围内直接检查；主观偏好和不可推断的权限才需要用户回答。

## 提问示例

背景很少时，可从以下三项中选当前最关键的 1—3 项，避免机械照读：

1. “这个知识库主要给谁用？你最想先用它完成哪件事？”
2. “目前资料主要放在哪里？可以先从哪一小批开始？”
3. “你主要用电脑还是手机？每周大约愿意花多少时间整理？”

用户已明确想要“星空拖动”时，记录为星空图谱偏好，展示同类实际效果，再核对设备与笔记关联情况；不重复让用户从不相关的桌面首页中选择。

## 形成可执行画像

进入蓝图前，将已知信息压缩为一份短摘要：

- 首要任务与第一项成果。
- 当前路线：新建、已有库整理、视觉调整、资料导入或维护。
- 目标库位置和允许处理的资料范围。
- 使用端、读写角色、时间费用和外部处理边界。
- 组织、浏览与视觉偏好；明确哪些是默认选择。
- 当前可用工具、缺失能力及替代路径。
- 本轮小样本、验证方法与下一动作。

已有信息足够完成下一步时就继续，不以“画像尚未填满”为由停住。若用户更改目标，先评估哪些已做工作可复用，再调整后续路线。

## 续接

沿用主入口约定的进度记录位置，只保存继续工作需要的内容：确认项、默认项、待确认项、完成阶段、已处理批次、已改文件、验证证据、恢复点和下一动作。

不要把敏感原文、密码、密钥或完整录音转写复制进进度摘要。续接时核对目标路径和相关文件是否变化；已完成阶段不重跑，发生并发修改的文件重新读取后再处理。
