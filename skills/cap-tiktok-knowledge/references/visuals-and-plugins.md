# 知识库视觉呈现与插件选型

在用户选择视觉效果、提供参考图，或希望增强图谱、画布、知识页面时读取本文件。目标是让知识更容易浏览、理解和复用；视觉方案必须展示真实知识内容。

## 先分清用户要改变什么

| 对象 | 负责什么 | 处理方式 |
|---|---|---|
| Obsidian 内置功能 | 图谱、Canvas、Bases 等知识视图 | 优先检查已有功能能否满足要求 |
| 社区插件 | 增加三维图谱、手绘、画布增强等能力 | 根据所选效果核对依赖并按需配置 |
| 主题与 CSS | 配色、字体、圆角、间距、界面布局 | 保留现有内容与工作习惯，做局部可恢复调整 |
| 示例库／模板 | 知识组织与页面的现成示例 | 借鉴适合的部分，先检查结构与示例资料 |
| Agent skill | 指导 AI 生成内容、配置视图与检查效果 | 阅读实际 `SKILL.md`、资源、许可证和工具要求 |

不要把上述对象统称为“skill”。有 `SKILL.md` 只证明存在技能入口，不证明效果、质量或当前环境兼容。技能通常提供生成能力，不能直接当作固定风格图库。

## 看图选择知识呈现方式

用户已明确喜欢“像星空一样拖动的知识图谱”时，从二维图谱开始试用，再按需要展示增强选项。该偏好只属于当前用户；对其他用户仍要根据用途推荐，不强制所有库使用图谱。

| 呈现方式 | 具体效果 | 适合的任务 | 基础与扩展 |
|---|---|---|---|
| 二维星空图谱 | 笔记为星点、内部链接为连线，平移、缩放、点击进入笔记 | 看主题群落、枢纽与跨领域关联 | 内置 Graph View；需要图片节点、额外过滤等时研究 Extended Graph |
| 三维星系图谱 | 在立体空间旋转、缩放和探索笔记网络 | 空间探索与整体展示 | 研究 3D Graph 等社区插件；同时保留二维浏览方式 |
| Canvas 卡片知识地图 | 把笔记片段、图片、PDF、链接分组排列并连接 | 研究梳理、流程说明、方案对比 | 内置 Canvas；需要节点样式、折叠、演示等时研究 Advanced Canvas |
| 手绘知识白板 | 图形、箭头、文字和笔记链接组成可编辑白板 | 概念讲解、关系图、教学与思考 | Excalidraw 插件，按当前格式生成可编辑文件 |
| 卡片／表格知识索引 | 按主题、类型、状态筛选资料，卡片可展示封面 | 查找、阅读列表、案例库和项目资料库 | 内置 Bases；复杂查询页面再考虑 Dataview |

根据任务继续扩展：层级思维导图、时间线、带关系说明的概念图、地图、数据图表和交互索引。不要仅为选项数量加入不相关效果，也不把每个新增效果都当作必须安装的新插件。

用户要比较时，优先给五种有明显差异的知识呈现方式；若明确要求十个，再检索足够候选。区分“十个技能”“十个插件”和“十种效果”，不把同一项目的分支或同一示例重复计数。

## 按需确认的视觉维度

每轮只问影响当前选择的少量问题，其他维度给合理默认值，避免变成问卷。

- **浏览任务**：找某条资料、探索关联、学习一个主题、向别人讲解，还是展示全库。
- **范围与层级**：全库、某主题、某项目、当前笔记周边；先显示几层关系，哪些内容默认隐藏。
- **信息密度**：整体群落还是可读正文；何时显示标题、摘要、封面和关系说明。
- **交互**：拖动、缩放、旋转、悬停、筛选、展开分组、进入原笔记及返回导航。
- **视觉语言**：明暗、对比度、配色数量、字体大小、行宽、留白、圆角与背景；避免仅靠颜色区分主题。
- **内容载体**：纯文字、图片、PDF、录音摘要等如何进入视图，来源与原文件如何打开。
- **使用设备**：桌面与手机、触控与鼠标、屏幕尺寸、离线需求、低性能设备。
- **舒适与可达性**：文字可读、减少动画、键盘操作、避免过密连线与过小点击目标。
- **持续维护**：添加笔记后能否自动更新、配置有多少、谁维护、升级后如何恢复。

同一库可以同时有“全库图谱＋主题索引＋笔记正文”三个入口，无需让用户只能选一种。

## 预览与样本

1. 使用能覆盖主要资料类型和关系的少量真实笔记。用于比较的方案采用同一批内容和同一任务；已有库先选一个主题或项目，避免全库试改。
2. 原始资料与正文保留；索引、画布和图谱设置作为其上的呈现层。点击视图后应能回到实际笔记、来源和附件。
3. 样本至少展示知识入口、主题或关系视图，以及一篇实际知识笔记。按所选方案缩减展示，不用天气、时钟、待办数量或漂亮封面代替知识内容。
4. 明确标记预览来源：**作者示例**、**概念示意**、**当前库实测**。作者图片只说明参考效果，不能声称是当前用户资料生成的结果。
5. 展示作者示例时，读取主仓库当前 README 或示例目录，核对图片路径和上下文，链接回原项目；不借用无关主题图冒充技能输出。
6. 需要生成样本而缺少资料时，先使用用户已授权可访问的材料；若仅能做演示，使用明确标注的示例内容并说明尚未用用户资料验证。
7. 在 Obsidian 中检查打开、缩放、拖动、点击跳转、筛选和阅读。如果无法启动或检查界面，说明哪些文件或语法已检查、哪些交互尚未实测，不将生成文件等同于效果验收。

## 图谱中的关联必须有依据

- 内置图谱主要呈现真实内部链接。先做好知识之间的引用、主题归属和导航，再调整节点、连线与颜色。
- 建立链接时，应能解释两篇笔记的相关性；避免为制造星空密度批量插入无意义链接、空笔记或标签。
- 区分原文直接关联、用户确认关系与 AI 建议关系。需要语义相似度的功能另核对索引与计算方式，不能把普通链接图说成已完成语义分析。
- 分组优先沿用用户已有主题、标签或属性；选择能读懂的少量分类，保留文字或图例说明。
- 控制全库与局部图谱的范围、过滤、节点标题和力学参数，避免把大量不相关文件全部显示。操作前保存原设置，保留用户已有的筛选与自定义。
- 图谱大、节点多、连线密都不是验收成绩。验证用户是否能找到某个主题、理解一条关系并进入有依据的内容。

## 插件与外部技能的选择和应用

先检查当前 Obsidian 版本、平台、已启用插件、主题、样式片段与可用操作工具。在能完成任务的前提下选择维护负担较小的组合。

使用当次通过官方文档、主仓库及 Obsidian 社区插件目录核对：

- 当前维护、发布与兼容情况，移动端或桌面端限制；Extended Graph 是桌面端候选，不能默认手机可用。
- 额外插件、运行环境、外部服务、付费项目、数据去向及离线能力；需要云端处理时说明发送什么材料及去向，沿用已明确的授权范围。
- 样本数据量下的载入、拖动、标签可读性与设备表现。三维、模糊、动画或大图造成卡顿时，减少范围或特效，并提供二维或列表入口。
- 文件格式、导出方式与停用后的可用性。扩展属性不能承诺在纯 Obsidian 或其他设备中完整还原。
- 项目许可证与引用要求。参考其决策和格式，避免无依据地整包复制或自动执行下载到的脚本。

用户选择并授权应用方案后执行必要配置，不反复请求同一授权。用户只要求看效果或研究候选时，不据此安装、切换主题或批量修改知识库。缺少工具、依赖或访问能力时，提供当前可执行的替代路径。

实际修改：保存当前配置与相关样式的检查点 → 在样本上应用最小改动 → 重新打开并检查 → 展示结果 → 沿用用户反馈调整。检查点放在不会被当作启用样式的位置。出现回归时恢复最近可用状态并重新判断原因，不叠加无效改动。

通过后记录已选效果、版本、必要插件、设置位置、样本范围、已实测交互和恢复方式；后续增量更新沿用该方案。

## 已核验方向的主源入口

以下是检索与核对入口，不表示它们已安装、已经测试，或在任何环境都可直接运行。功能、版本和安装方式使用当次再核对。

### Obsidian 功能与插件

- [Graph View](https://help.obsidian.md/plugins/graph)：内置二维图谱及分组、过滤、显示和力学设置。
- [Canvas](https://help.obsidian.md/plugins/canvas)：内置可拖动的笔记、媒体与链接卡片画布。
- [Bases](https://help.obsidian.md/bases)：基于实际笔记和属性的多种资料视图。
- [3D Graph](https://github.com/Apoo711/obsidian-3d-graph)：三维图谱候选；核对当前插件目录名称与平台支持。
- [Extended Graph](https://github.com/ElsaTam/obsidian-extended-graph)：原生图谱增强候选，包括节点图片、形状、筛选和视图设置；桌面端。
- [Advanced Canvas](https://github.com/Developer-Mike/obsidian-advanced-canvas)：Canvas 样式、关系、分组与演示增强。
- [Excalidraw](https://github.com/zsviczian/obsidian-excalidraw-plugin)：在 Obsidian 中编辑和浏览手绘白板。

### 可参考的真实 Agent skills

- [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills)：`obsidian-markdown`、`obsidian-bases`、`json-canvas` 是格式与生成基础，不能包装成三套成品视觉风格。
- [obsidian-layout-adjustment](https://github.com/Ar9av/obsidian-wiki/blob/main/.skills/obsidian-layout-adjustment/SKILL.md)：按用户审美调整当前库的界面、样式和布局，并截图验证。未发现专属成品风格图库，不用主仓库其他截图冒充其结果。
- [Axton Obsidian Visual Skills](https://github.com/axtonliu/axton-obsidian-visual-skills)：`obsidian-canvas-creator`、`excalidraw-diagram`、`mermaid-visualizer` 负责知识内容可视化；本次研究时标注为实验性，使用时重查状态。主 README 有作者示例，不能据此声称负责整库界面美化。
- [claude-canvas](https://github.com/AgriciDaniel/claude-canvas)：多种知识画布与自动布局；面向 Claude 插件结构，使用前适配路由、依赖和当前宿主，不能承诺在其他环境原样可用。
- [lexbritvin/obsidian-skills-pack](https://github.com/lexbritvin/obsidian-skills-pack)：可研究图谱配置、Dataview、Meta Bind、Charts 的技能正文；它们是视图生成和配置能力，主 README 未提供的效果图不能自行补成作者产物。

不要把这些外部项目设为本技能的必装依赖。能使用 Obsidian 原生文件和现有能力完成任务时，直接完成；只有明确需要某项额外能力时再研究对应项目。
