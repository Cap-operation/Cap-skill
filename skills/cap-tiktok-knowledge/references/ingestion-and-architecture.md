# 资料加工与知识结构

在盘点、设计小样、导入或整理已有库时读取。目标是把材料加工成可追溯、可检索、可复用的知识，结构复杂度服从用户任务和维护预算。

## 先看环境与代表样本

确认目标库的绝对路径、新建或已有、设备与平台、现有同步方式、能访问的范围，以及当前是否能操作 Obsidian。路径有歧义时先定位目标，不能猜一个库就开始写。

盘点先读取文件名、格式、数量与少量代表内容；根据授权再扩大。目录、插件、主题、手工首页和笔记属性都是现有约定，先理解再改。记录当前具备的文本读取、PDF、OCR、录音转写、网页获取、Obsidian 控制能力；缺工具时保留待处理项，不能用摘要替代不存在的转写。

## 按资料类型处理

| 输入 | 加工方式 | 保留什么 |
|---|---|---|
| Markdown、纯文本 | 识别现有结构和链接，保留有用格式，按任务决定是否拆分 | 原文件、标题、引用路径、原有关系 |
| PDF、Word、幻灯片 | 先区分可提取文本、扫描件、表格与图示；按可用工具转换 | 来源文件、页码／章节、关键图表与表头语义 |
| 录音、视频 | 先转写，再提取决策、理由、方法、案例或行动项；含糊内容待确认 | 原文件、可核实的时间位置、转写与摘要各自状态 |
| 图片、截图、手写内容 | 有识图能力才提取；分开记录看见的文字和对图的解释 | 原图、识别不确定处、必要局部引用 |
| 网页、文章、论文 | 读取实际内容，保存标题、作者、原始链接和获取日期；按任务提炼 | 可访问来源和具体位置；受限内容标为未获取 |
| 聊天、邮件、会议记录 | 区分发言、决定、未决问题与行动；敏感与无关部分按范围排除 | 会话／消息标识、发言上下文、真实责任人与日期 |
| 表格、CSV、结构化数据 | 保留原始数据，明确列含义、单位与时间范围；需要时另建说明页 | 原表、数据口径、计算方法；不把每一行都变成笔记 |

音视频、Office、OCR 和在线获取都属于能力分支，并非保证自动支持。没有转换能力时，明确需要的可读中间材料，继续处理其他资料。

## 四种知识对象

只引入当前任务需要的类型；小库不必拆成四个文件夹。

- **来源**：原文及其可核查摘要，负责证据。原件保持不变，必要时存链接而不是重复拷贝大附件。
- **知识**：回答一个明确问题的解释、方法、判断或案例，链接来源并说明适用条件。
- **主题导航**：围绕用户的问题组织入口，给阅读顺序和当前结论；有用时才创建 MOC（主题索引）。
- **应用成果**：方案、决策、课程、操作清单或其他工作输出，记录复用了哪些知识以及实践反馈。

例如：一次会议 → 来源纪要 → “如何处理某类问题”的方法笔记 → 主题索引 → 本次操作清单 → 执行复盘。

## 最小组织方案

从最少必要的收集入口、主题入口、附件位置和归档规则开始。下面是可选骨架，先沿用用户已有约定；不要为模仿流派强制搬家。

```text
知识库/
  首页.md
  收集箱/
  来源/
  知识/
  主题/
  成果/
  附件/
  _meta/
```

项目驱动用户可以让项目成为主入口；研究用户可以让问题／主题成为主入口；业务团队可以按流程与岗位导航。PARA、卡片盒、领域目录、MOC 都是可选方法，按资料与使用方式组合，而非必选题。

文件名以用户能理解的标题为主。仅在必要时加入日期、主题或稳定标识以防重名。控制目录深度和标签同义词；不要同时维护三套含义相同的分类。标签、属性、目录、链接各有职责：类型与状态适合属性，主题关系适合有意义的链接。

## 来源与最小属性

仅保留使用或筛选会用到的字段。下面是语义建议，不要求所有笔记都有完整字段：

| 字段 | 用途 |
|---|---|
| `type` | 来源、知识、主题、成果等类型 |
| `status` | 待整理、草稿、已核对、已过期等实际状态 |
| `source` | 真实 URL、原文件或来源笔记链接 |
| `updated` | 内容实际修订日期，不能把复制日期当事实更新日期 |
| `owner`、`review_after` | 团队责任人和复核日期，仅在确实需要时加入 |

对关键结论记录：结论内容、依据的文件／段落／页码／时间位置、适用条件、是否推断、是否经过用户核对。无法核实的位置留空或写待核实，不编造定位。

同一结论有冲突来源时并列保留时间、范围和证据，不擅自选择听起来更合理的版本。重要术语统一名称，可用别名承接已有称呼。

## 链接要能解释关系

只有关联可以用一句话解释时才添加：支持某判断、是某步骤的前提、是一个例子、与另一观点冲突、更新了旧方法等。

先搜索现有笔记，再决定链接或新建；不以关键词碰巧相同建立关系，不为星空更密设最低连线数。不要批量创建只有标题的概念壳。Canvas 连线是画布关系，不自动等同于笔记正文中的双向链接；不同视图的依据要说明。

## 小样、批次与增量

1. 选能代表格式和用途的少量资料；确认本批输入、预期笔记与验收任务。
2. 记录每个来源的稳定标识（原路径／规范 URL；适用时用内容指纹），来源变更依据、处理状态和生成文件。
3. 先查库中已有结果。未变的来源跳过；变更来源更新关联结果，保留用户手写段落，避免整页重生覆盖。
4. 对重复内容给出合并建议；用户已授权整理时处理范围内的可逆合并，否则列出具体方案。保留原件或合并前副本。
5. 移动／更名后更新受影响的内部链接、嵌入、附件与查询；无法确定引用范围时先保留原路径。
6. 每批交付已处理、跳过、失败与待核对清单。失败项不伪装成成功，重试先检查是否已经产生输出。

处理记录可以放在已有项目日志或 `_meta/knowledge-guide.md`，不额外强制数据库。不要记录密钥；不要为了去重而把私密原文复制到日志。

## 验收区别

- **文件检查**：YAML／JSON 语法、Canvas 节点与边引用、文件路径、来源定位与重复文件。
- **内容检查**：结论忠于来源，推断有标记，关键背景没有丢失，原文与生成内容可区分。
- **实际使用**：用户能完成约定的查找与产出任务；在目标设备打开所选视图，没有遮挡、缺图或无法操作。

只做了文件检查时报告“文件检查通过，显示效果尚未验证”。没有语义索引／检索工具时，不把普通链接库称为已经建好的 AI 问答系统；需要问答就另验引用质量、找不到答案时的处理和更新方式。
