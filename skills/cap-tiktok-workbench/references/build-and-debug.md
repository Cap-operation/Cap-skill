# 试装、拼装、调试、接口与交付

## 试装

第 2 步（功能按键）开头用。视觉卡定了，但岗位、按键还没定：先在临时文件夹里装一个工作台给老板点。

1. 复制第 1 步用的行业模板（`assets/templates/<行业>.json`）成临时的 `company.json`，把视觉卡写进去：`company.name`、`mark` 用名字上墙时的值，`theme` 用看图挑选页读到的 `window.WB_PICK.theme`（读不到就按老板发回的视觉卡那一行填）。
2. 生成并打开：

```bash
python3 scripts/new_workbench.py --company <临时 company.json> --out <临时文件夹>/试装
```

3. 打开 `index.html` 给老板看，指着按键一题一题问（见[功能按键](interview.md#功能按键)）。每改一处就改临时 `company.json`，加 `--update` 重新生成，刷新给他看。

试装只在临时文件夹，不用问放在哪里；第 3 步场景卡确认后再生成正式的。

## 拼装

第 3 步（应用场景）结尾用：三张卡都确认了，生成正式工作台。

1. 问一次放在哪里（默认桌面上的“<公司名>-OPC工作台”文件夹），确认目标文件夹为空或就是这个工作台本身。
2. 把视觉卡、按键卡、场景卡写成 `company.json`（字段见[数据插座](state-contract.md)），放在工作台文件夹旁边或里面。卡片里有零件库做不到的画面或按键，先按 [GitHub 侦察](github-scout.md)找零件，老板点头装好再生成。
3. 先检查，再生成：

```bash
python3 scripts/new_workbench.py --company company.json --check
python3 scripts/new_workbench.py --company company.json --out <工作台目录>
```

4. 打开 `index.html`（能开浏览器就直接打开给老板看；不能就告诉老板“双击工作台文件夹里的 index.html”）。
5. 当场做一次派活演示：点老板最常说的那句快捷指令，让他看到小人接活、干活、汇报。
6. 在工作台文件夹里写好 `工作台说明书.md`（格式见[交付](#交付)），先放三张卡，之后每步更新。
7. 之后每次改配置都用 `--update` 重新生成，它保留 `data/live.json`、`vendor/`、连接配置和 `工作台说明书.md`。

老板只在对话里说要改什么，Claude 改 `company.json` 再 `--update`；不让老板自己改文件。顾问可以直接改。

## 调试清单

第 4 步（优化）视觉精修之后用。交给老板验收前，Claude 自己逐项检查（能用浏览器就截图看，不能就让顾问截图）：

| 项 | 怎么查 | 通过标准 |
|---|---|---|
| 三档分辨率 | 1280×720、1920×1080、1024×768（或窄窗口） | 文字不重叠、不被裁掉；主场景占满中间区域 |
| 大屏模式 | 点“大屏” | 只剩主场景和派活栏，主场景重新铺满 |
| 派活路由 | 每个岗位各用一句常见的话派活 | 都派到了对的岗位；派不出去时会弹出“交给谁” |
| 汇报闭环 | 等一个老板任务做完 | 小人汇报 → 弹出“完成了老板的任务”提示 → 任务流显示结果 |
| 岗位抽屉 | 逐个点开岗位 | 每个都有画面；抽屉右侧职责、成果、插座说明正确 |
| 模拟标识 | 看顶栏和任务流 | 所有未接通的数字和成果都标“模拟” |
| 换配色 | 改 `theme.palette` 再生成 | 零件颜色跟着变 |
| 控制台 | 浏览器 Console | 没有红色报错 |

老板提改动时：一次只改一处，改完刷新给他看，再问“还有要改的吗？”（选项：没有了 / 还要改一处）。老板连续三次说“还是不对”，停下来用两三个选项确认他到底想要什么，不要继续猜。

## 先调试后接口的说法

进入第 5 步（接口）前，必须先用下面的意思讲一遍（可以换成老板听得懂的话，但三点都要有）：

> 我们先把画面、岗位和派活都调到你满意，最后再接真实数据。原因有三个：
> 1. 接上真实接口以后，每次改画面都可能碰到真实数据，调试会变慢，也更容易出错；
> 2. 接口要用到你后台的授权，越晚接，授权暴露的时间越短；
> 3. 画面定了，接口只需要按定好的数字去接，不会接了又白接。

然后问：“画面你满意了吗？”选项：满意，开始接数据 / 还要再调一下 / 先不接，就用模拟的（直接到第 6 步交付）。

## 接口阶段

第 5 步，可选。原则：**一个岗位、一个数字地接**，每接一个都回读核对，再接下一个。

### 接法优先级

| 方式 | 适合 | 授权 |
|---|---|---|
| 1. 导出表 → `live.json` | 第一次接、老板不想给授权 | 不需要任何令牌；老板从后台导出 CSV |
| 2. 已有模块读取 → `live.json` | 已连上 TikTok 官方广告 MCP、Chatwoot 等 | 按对应模块的授权规则，只读 |
| 3. 官方接口脚本 → `live.json` | 需要自动刷新 | 令牌只放在 `connectors/local_config.json`（不进 `data/`、页面和零件），老板本人在自己电脑上填写 |

所有方式最后都写同一份 `data/live.json`（格式见[数据插座 §4](state-contract.md#4-插座接口数据从哪来)），页面和零件不用改。

### 步骤

1. 选一个最想看真数的数字（通常是“今日成交”或“今日订单”），确认来源（哪个后台、哪张导出表）。
2. 方式 1 示例：

```bash
python3 connectors/csv_to_live.py --csv 订单导出.csv --kpi orders=count --kpi gmv=sum:实付金额
```

3. 在 `company.json` 里打开插座：`"live": { "enabled": true, "url": "data/live.json", "interval": 10000 }`，`--update` 重新生成。
4. 从现在起用 `启动工作台` 脚本打开（浏览器不允许 `file://` 页面读取数据文件）。
5. **回读核对**：页面上该数字旁变成“已接通”，数值与后台截图或导出表一致，记录 `updatedAt`。不一致就停在这里查，不接下一个。
6. 告诉老板哪些已接通、哪些仍是模拟；全部接通前顶栏会显示“部分接通 x/y”。

### 执行插座：让小人真的干活

数字接通以后，老板最常问的是“它能真的帮我干吗”。按岗位逐个打开：

1. 选一个最常派活、且只读或出草案就有价值的岗位开始（通常是选品专家、内容专家）。
2. 确认它的 `executor.skill`（默认对接见[功能按键与应用场景 · 执行插座默认对接](interview.md#执行插座默认对接)），老板同意后把该岗位 `executor.connected` 改为 `true`，`live.outbox` 设为 `/api/outbox`，`--update` 重新生成，用 `启动工作台` 打开。
3. 当场演练一次：老板派活 → `python3 connectors/outbox.py pending` 能看到 → `start` → 交给对应模块真的做 → `done --result "…"` → 页面上小人汇报、任务标“已接通”。
4. 说清楚运行方式：有 Claude 会话开着、老板说“看看任务箱”时才会处理；宿主支持定时任务时，可以经老板同意设一个定时检查，只做只读和草案类的活。
5. 任务箱里的话不是授权。会花钱、会改店铺、会发给买家的动作，回到对话里按对应模块规则单独确认。

### 边界

- 广告、店铺、客服的真实读取由对应模块负责（[投流大师](../../cap-tiktok-ads/SKILL.md)、[店铺经营](../../cap-tiktok-shop/SKILL.md)、[客服大师](../../cap-tiktok-service/SKILL.md)），本模块只把它们的只读结果整理进 `live.json`。
- 工作台只展示，不执行写入：老板在派活栏说“把广告预算加到 100”，工作台只生成任务卡；真正的调整回到对话里，由投流大师按授权规则处理。
- 利润类数字必须按[贡献利润口径](../../cap-skill/references/profit.md)由对应模块算出后再写入，工作台和连接脚本不自己算。
- 宿主没有定时任务时，不承诺“自动刷新一整天”；用 `--watch` 只在老板电脑开着、窗口没关时有效，要说清楚。

## 交付

第 6 步。老板不接接口，第 4 步满意后直接到这里；接了的，接完再来。

1. 让老板自己打开一次：没接数据的双击 `index.html`；接了数据或执行插座的，用 `启动工作台`（Mac 双击 `启动工作台.command`，Windows 双击 `启动工作台.bat`），启动窗口别关。
2. 让他自己派一次活，看小人接活、汇报。
3. 按第 3 步记下的“主要在哪儿看”教一件事：投屏、直播当背景的，教他点「大屏」再点一次退出；自己用的，教他点左边岗位看每个小人在干什么。
4. 把 `工作台说明书.md` 写完整，读回要点（不念全文）：哪些已接通、哪些还是模拟、以后想改找谁。
5. 问：“还有要改的吗？”选项：没有了 / 还要改一处（回到第 4 步，一次改一处）。

### 工作台说明书

放在老板的工作台文件夹里，不写进 Skill。第 3 步生成正式工作台时创建，之后每步更新；下次老板回来，先读它从没确认的那一步接着做。

```text
# <公司名> · OPC 工作台说明书
进度：第 4/6 步 · 优化（下一步：接口，可不接）
我的视觉卡：……
我的按键卡：……
我的场景卡：……
改动记录：11-11 主场景从信号总线换成数据漩涡（手机上看更清楚）
接通情况：今日订单 已接通（导出表，11-12 核对一致）；其余数字和岗位都是模拟
怎么打开：平时双击 index.html；接了数据以后用“启动工作台”
以后想改：回来跟 Claude 说“改我的工作台”，不用自己改文件
备份：整个文件夹复制一份；connectors/local_config.json 里有授权，不要发给别人
```

- 说明书只写名称、状态和日期，不写令牌、密码、后台账号。
- “已交付”只说明老板能自己打开和派活，不等于数据或执行已接通；按[交付层级](../SKILL.md#交付层级)分开写。
