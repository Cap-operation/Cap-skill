# 生成、调到满意、交付与接数据

## 生成正式工作台

第 2 步（定公司）两道题问完就用，不先装临时版本。

1. 复制第 1 步用的行业模板（`<本技能文件夹>/assets/templates/<行业>.json`）成临时文件夹里的 `company.json`（生成器要求工作台文件夹是空的，不要先放进去），写入：
   - 视觉卡：`company.name`、`mark` 用名字上墙时的值，`theme` 用看图挑选页读到的 `window.WB_PICK.theme`（读不到就按老板发回的视觉卡那一行填）；
   - 市场和岗位：按[定公司](interview.md)的两道题；
   - 快捷指令、顶栏数字、口号、岗位画面：按[自动配好，不问](interview.md#自动配好不问)。
2. 放在哪里：默认桌面上的“<公司名>-OPC工作台”文件夹，生成后告诉老板一声。那个文件夹已经有别的东西（不是这个工作台本身）时，才问一次放哪里。
3. 卡片里有零件库做不到的画面，先按 [GitHub 侦察](github-scout.md)找零件，老板点头装好再生成。
4. 先检查，再生成：

```bash
python3 <本技能文件夹>/scripts/new_workbench.py --company company.json --check
python3 <本技能文件夹>/scripts/new_workbench.py --company company.json --out <工作台目录>
```

5. 打开 `index.html`（能开浏览器就直接打开给老板看；不能就告诉老板“双击工作台文件夹里的 index.html”）。
6. 当场派一次活：点第一句快捷指令，让他看到小人接活、干活、汇报。
7. 读回[公司卡](interview.md#公司卡)，只问一次“这样对吗”。
8. 在工作台文件夹里写好 `工作台说明书.md`（格式见[交付](#交付)），之后每步更新。生成器还会放进 `AGENTS.md`、`CLAUDE.md`（只在没有时新建）和 `给AI看的说明/`，不用另外写。
9. 生成器会把这次用的配置另存到工作台文件夹的 `company.json`。之后每次改配置就改这一份，再用 `--company <工作台目录>/company.json --out <工作台目录> --update` 重新生成；它保留 `data/live.json`、`vendor/`、连接配置和 `工作台说明书.md`。

老板只在对话里说要改什么，Claude 改 `company.json` 再 `--update`；不让老板自己改文件。顾问可以直接改。

## 调到满意

第 3 步。老板想改哪里说哪里：一次只改一处，改完刷新给他看，再问“还有要改的吗？”（选项：没有了 / 还要改一处）。视觉怎么定位、怎么对比、“主要在哪儿看”见[视觉挖掘 · 第 3 步的视觉调整](visual-discovery.md#第-3-步的视觉调整)。

- 老板改岗位、快捷指令、顶栏数字：直接改，改完读回改动的那一行，不再读整张卡。
- 老板说“没有了”：Claude 自己过一遍下面的调试清单，有问题自己修好再说“可以了”；清单不让老板参与。
- 老板连续三次说“还是不对”，停下来用两三个选项确认他到底想要什么，不要继续猜。
- 老板这时问“能不能接真实数据”：先用下面一句话说法讲清，交付后再接。

### 调试清单

交给老板前，Claude 自己逐项检查（能用浏览器就截图看，不能就让顾问截图；没有浏览器也没有顾问的，按 [SKILL.md 宿主与工具](../SKILL.md#宿主与工具)请老板截一张全屏图，其余项标“待验证”）：

| 项 | 怎么查 | 通过标准 |
|---|---|---|
| 三档分辨率 | 1280×720、1920×1080、1024×768（或窄窗口） | 文字不重叠、不被裁掉；主场景占满中间区域 |
| 大屏模式 | 点“大屏”，再点一次 | 左右两栏收起，只留顶栏（名字、数字、「大屏」「暂停」）、主场景和派活栏，主场景铺满；再点一次「大屏」恢复三栏 |
| 派活路由 | 每句快捷指令、每个岗位各用一句常见的话派活 | 都派到了对的岗位；派不出去时会弹出“交给谁” |
| 汇报闭环 | 等一个老板任务做完 | 小人汇报 → 弹出“完成了老板的任务”提示 → 任务流显示结果 |
| 岗位抽屉 | 逐个点开岗位 | 每个都有画面；抽屉右侧职责、成果、插座说明正确 |
| 模拟标识 | 看顶栏和任务流 | 所有未接通的数字和成果都标“模拟” |
| 换配色 | 改 `theme.palette` 再生成 | 零件颜色跟着变 |
| 控制台 | 浏览器 Console | 没有红色报错 |

### 先调试后接口的说法

老板在交付前要接真实数据时，用一句话讲清（意思不变，可以换说法）：

> 先把画面和派活调到你满意再接真实数据：接上以后每改一次画面都可能碰到真实数据，授权也越晚给越安全，画面定了接口只接一次就够。

然后回到当前这一步；交付时再问要不要接。

## 交付

第 4 步，第 3 步满意后直接到这里。

1. 让老板自己打开一次：没接数据的双击 `index.html`；接了数据或执行插座的，用 `启动工作台`（Mac 双击 `启动工作台.command`，Windows 双击 `启动工作台.bat`），启动窗口别关。
2. 让他自己派一次活，看小人接活、汇报。
3. 按第 3 步问到的“主要在哪儿看”教一件事：投屏、直播当背景的，教他点「大屏」再点一次退出；自己用的，教他点左边岗位看每个小人在干什么。
4. 把 `工作台说明书.md` 写完整，读回要点（不念全文）：哪些已接通、哪些还是模拟、以后想改找谁。
5. 最后说一句：“以后想接真实数据、让小人真的干活，随时跟我说；想自己用 AI 编程工具改，打开这个文件夹就行，里面有给 AI 的说明。”不追问，不再问“还有要改的吗”。

### 工作台说明书

放在老板的工作台文件夹里，不写进 Skill。第 2 步生成正式工作台时创建，之后每步更新；下次老板回来，先读它从没做完的那一步接着做。

```text
# <公司名> · OPC 工作台说明书
进度：第 3/4 步 · 调到满意（下一步：交付）
我的视觉卡：……
我的公司卡：……
改动记录：11-11 主场景从信号总线换成数据漩涡（手机上看更清楚）
接通情况：今日订单 已接通（导出表，11-12 核对一致）；其余数字和岗位都是模拟
怎么打开：平时双击 index.html；接了数据以后用“启动工作台”
以后想改：回来跟 Claude 说“改我的工作台”，不用自己改文件
备份：整个文件夹复制一份；connectors/local_config.json 里有授权，不要发给别人
```

- 说明书只写名称、状态和日期，不写令牌、密码、后台账号。
- “已交付”只说明老板能自己打开和派活，不等于数据或执行已接通；按[交付层级](../SKILL.md#交付层级)分开写。

## 接数据（可选）

交付之后，老板说要接再做。原则：**一个岗位、一个数字地接**，每接一个都回读核对，再接下一个。先问：“你现在用哪些后台或表格？”（TikTok Shop 后台 / Shopify 后台 / 广告账户 / Excel 或飞书表格，可多选），记进各岗位 `socket`。

### 接法

接法优先级（导出表 → 已有模块只读 → 官方接口脚本）、每个岗位接什么数据、顶栏数字怎么算、连接脚本规格和给 AI 编程工具的任务单，见[接接口](connect-guide.md)。所有方式最后都写同一份 `data/live.json`（格式见[数据插座 §4](state-contract.md#4-插座接口数据从哪来)），页面和零件不用改。

### 步骤

1. 选一个最想看真数的数字（通常是“今日成交”或“今日订单”），确认来源（哪个后台、哪张导出表）。
2. 方式 1 示例：

```bash
python3 connectors/csv_to_live.py --csv 订单导出.csv --kpi orders=count --kpi gmv=sum:实付金额
```

3. 在 `company.json` 里打开插座：`"live": { "enabled": true, "url": "data/live.json", "interval": 10000 }`，`--update` 重新生成。
4. 从现在起用 `启动工作台` 脚本打开（浏览器不允许 `file://` 页面读取数据文件）。
5. **回读核对**：页面上该数字旁变成“已接通”，数值与后台截图或导出表一致，记录 `updatedAt`。不一致就停在这里查，不接下一个。
6. 告诉老板哪些已接通、哪些仍是模拟；全部接通前顶栏会显示“部分接通 x/y”。更新说明书的接通情况。

### 执行插座：让小人真的干活

数字接通以后，老板最常问的是“它能真的帮我干吗”。按岗位逐个打开：

1. 选一个最常派活、且只读或出草案就有价值的岗位开始（通常是选品专家、内容专家）。
2. 确认它的 `executor.skill`（默认对接见[定公司 · 执行插座默认对接](interview.md#执行插座默认对接)），老板同意后把该岗位 `executor.connected` 改为 `true`，`live.outbox` 设为 `/api/outbox`，`--update` 重新生成，用 `启动工作台` 打开。
3. 当场演练一次：老板派活 → `python3 connectors/outbox.py pending` 能看到 → `start` → 交给对应模块真的做 → `done --result "…"` → 页面上小人汇报、任务标“已接通”。
4. 说清楚运行方式：有 Claude 会话开着、老板说“看看任务箱”时才会处理；宿主支持定时任务时，可以经老板同意设一个定时检查，只做只读和草案类的活。
5. 任务箱里的话不是授权。会花钱、会改店铺、会发给买家的动作，回到对话里按对应模块规则单独确认。

### 边界

- 广告、店铺、客服的真实读取由对应模块负责（[投流大师](../../cap-tiktok-ads/SKILL.md)、[店铺经营](../../cap-tiktok-shop/SKILL.md)、[客服大师](../../cap-tiktok-service/SKILL.md)），本模块只把它们的只读结果整理进 `live.json`。
- 工作台只展示，不执行写入：老板在派活栏说“把广告预算加到 100”，工作台只生成任务卡；真正的调整回到对话里，由投流大师按授权规则处理。
- 利润类数字必须按[贡献利润口径](../../cap-skill/references/profit.md)由对应模块算出后再写入，工作台和连接脚本不自己算。
- 宿主没有定时任务时，不承诺“自动刷新一整天”；用 `--watch` 只在老板电脑开着、窗口没关时有效，要说清楚。
