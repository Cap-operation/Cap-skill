# 风格配方

第 1 步配合[视觉挖掘](visual-discovery.md)使用。目标是让每个老板的工作台一看就不一样，而且和他的生意对得上，不是同一个看板换颜色。

## 怎么让老板选

1. 第一分钟先用行业模板生成**风格画廊**：`python3 scripts/new_workbench.py --template <行业> --gallery --out <临时文件夹>`；场景卡确认后可以用老板自己的配置再生成一次（`--company <company.json> --gallery`）。画廊把零件库里每个主场景都实时跑一遍，顶部视觉控制台能当场切配色、背景、动感、庆祝、开场和品牌色。
2. 按下表给出 2–3 个推荐，第一个标“推荐”，每个用一句白话说它像什么（“像一间真实的像素办公室，小人会走来走去”）。
3. 问一个问题：“首页用哪个场景？”选完再问配色（给 2–3 个推荐配色）。
4. 岗位模块默认按下面“岗位 → 模块”自动配好，读回一句“点开每个岗位会看到…”，老板不满意再单独换。

不能打开画廊时（只能聊天的客户端），用一句话描述每个场景，并说明“拼好后可以随时换”。

## 主场景推荐

| 情况 | 第一推荐 | 备选 | 理由 |
|---|---|---|---|
| 一人公司、想展示“AI 团队在干活” | `pixel-office` 像素办公室 | `neural-galaxy` | 小人走动、汇报最有“团队感” |
| 给客户、投资人、学员展示 | `neural-galaxy` 神经星河 | `pixel-office`、`data-vortex` | 第一眼最震撼 |
| 内容工厂、短视频矩阵 | `pipeline` 流水线 | `energy-flow` | 一条内容从素材到发布的流动最直观 |
| 投流、数据驱动 | `energy-flow` 能量流体 | `node-matrix` | 任务和流量像能量一样流向各岗位 |
| 多市场、多国家出海 | `globe` 全球市场 | `data-vortex` | 一眼看到货卖到哪里 |
| 年轻、潮流、科技感品牌 | `neon-grid` 霓虹赛博 | `data-vortex` | 赛博风最抓眼 |
| 供应链、工厂、流程多 | `node-matrix` 信号总线 | `pipeline` | 信息在各环节之间传递最清楚 |
| 岗位很多（10 个以上） | `neural-galaxy` | `node-matrix` | 能放下更多节点而不拥挤 |

老板说“要炫酷”“不要死板”时，不把 `pipeline`、`node-matrix` 作第一推荐（科技冷酷组先推数据漩涡，高级沉稳组先推能量流体），它们可放在岗位模块里。问老板时一律用画廊上的中文名，不说 id。

## 配色推荐

| 配色 | 气质 | 适合 |
|---|---|---|
| `cyber` 赛博青 | 科技、冷静 | 默认；投流、数据型 |
| `neon` 霓虹粉紫 | 潮、年轻、夜店感 | 美妆、潮玩、内容型 |
| `aurora` 极光绿紫 | 高级、平静 | 家居、宠物、健康 |
| `amber` 琥珀金 | 稳重、有钱感 | 工厂、供应链、给投资人看 |
| `jade` 翡翠绿 | 生机、增长 | 农产品、户外、出海新手 |
| `ice` 冰蓝 | 干净、轻盈 | 3C、工具、B2B |

## 岗位 → 模块（默认）

| 岗位 | 默认模块 | 换成 |
|---|---|---|
| 统筹助理 | `node-matrix` | `neural-galaxy` |
| 选品专家、供应链管家 | `globe` | `data-vortex` |
| 内容专家、店铺运营 | `pipeline` | `energy-flow` |
| 投流专家、独立站专家 | `energy-flow` | `node-matrix` |
| 达人经理 | `neural-galaxy` | `globe` |
| 客服专家 | `data-vortex` | `pipeline` |
| 财务管家 | `neon-grid` | `energy-flow` |
| 模板外的新岗位 | 按“它最像哪类工作”套上面一行 | — |

## 多元化规则

1. 岗位模块至少用 3 种不同零件；同一个零件最多给一半的岗位。
2. 主场景的零件不再作为超过 2 个岗位的模块（避免点开还是同一个画面）。
3. 同一位顾问连续交付的工作台，主场景 + 配色组合不重复（顾问能提供上一个工作台的配置时检查）。
4. 现有零件满足不了老板明确提出的画面（例如“要一个 3D 城市”“要直播间大屏”）时，进入[GitHub 侦察](github-scout.md)找开源项目，不硬套现有零件。
5. 颜色只通过配色和岗位 `color` 调整，不改零件代码；要改零件本身属于新零件，按[零件清单](parts-catalog.md#新零件入库)处理。
