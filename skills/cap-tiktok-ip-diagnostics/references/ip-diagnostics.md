# IP 检测与 TikTok 现象诊断

## IP 购买

询价话术和 Miya、IPRoyal、911Proxy 下单步骤见 [IP 购买规格](../../cap-tiktok-ip-purchase/references/purchase-specifications.md)；本文件只负责检测与诊断。

## 依据和原则

检测顺序和合格线按飞书「第 1 章 · 1.4 IP质量检测教程」的四个阶段：一、类型与归属地（ISP 还是 Hosting）；二、欺诈值与 DNS/WebRTC；三、网关和软路由；四、上机终检。飞书没写的项目，下面会标出依据或写“需核对”。

- 目标是原生的本地住宅宽带 IP，坚决不用机房 IP。
- 每项记录时间、设备、网络、节点/IP 标签。多个网站结果互相矛盾时标成“冲突”，不擅自选一个当真相。
- 这些网站都是浏览器端检测，TikTok App 能看到的更多；全部通过只算及格线，不代表 TikTok 一定不查、不保证账号和播放结果（飞书 1.4 原意）。

## IP 检测操作顺序

学员连好网络（小火箭或软路由）后，先固定当前节点和代理状态，再按下面顺序检测。每一步只打开一个网站，完成后截图，AI 确认后继续。

### 第 0 步：记录测试条件

先记录：

```text
检测日期和时间：
手机型号与 iOS 版本：
Wi-Fi（软路由）还是小火箭：
当前节点/代理名称：
是否已连接：
目标国家：
```

只问目标国家；购买的城市、类型、ASN 请用户对照订单页自己核对，第 1 步结果和订单对不上时再拿出来比，不在开头逐项追问。不要在记录中写入完整订阅链接、密码、UUID 或代理认证信息。

检测前先请用户把手机的时区、语言、地区调成和网络出口国家一致（只说要调成什么，不确定当前页面时要截图，不猜点击路径）。时区、语言和 IP 冲突，飞书 1.4 把它列为掉进隔离池的原因之一，所以要先调好再测；没调就测出来的不一致，不能据此让用户换 IP。

### 第 1 步：查 IP 类型和运营商（飞书阶段一）

默认打开 `IP2Location`（https://www.ip2location.com）查当前 IP，下面的判定都按 IP2Location 结果页的栏目写；`IPinfo`（https://ipinfo.io）没有 `Usage Type`、`AS Usage Type`、`Proxy Data` 这几栏，只作对照。在 IP2Location 结果页看：

- `Country`：和目标国家一致；`City` 允许同一国家内小范围数据库差异，差异大标待复核；
- `Usage Type` 和 `AS Usage Type`：两处都要是 `(ISP)`（如 `Fixed Line ISP`、`Mobile ISP`），飞书叫“双 ISP”；
- 右边 `Proxy Data` 一栏：好的 IP 这里基本都是空的（`-`）；
- `ISP` / `ASN`：要是真实的本地宽带商，美国例如 Comcast、AT&T、Spectrum、Verizon，或 S&T、Vyve 这类本地小运营商。

判定：

- **不通过**：类型显示 `Hosting`、`(DCH) Data Center/Web Hosting/Transit`；运营商名字带 `Cloud`、`Datacenter`、`Hosting`（机房包装的假住宅）。飞书写的是“直接弃用，绝不上机”，买的是什么产品都一样。
- **不通过**：类型显示 `Business`（商业宽带）。飞书原文把它和 Hosting 放在一起“直接淘汰”，括号里写“部分极品除外”，但没定义什么算极品。所以默认判不通过；学员想保留的，请【船长电商】工作人员确认，AI 不自己放行、不改判待复核。
- 只有一处是 ISP、另一处不是：待复核。

### 第 2 步：查欺诈值（飞书阶段二）

打开 `Scamalytics`（https://scamalytics.com），输入当前出口 IP，看 `Fraud Score` 和是否列入黑名单（Blacklisted）。

- `0–15`：安全区，进入下一步；
- `16–30`：观察区，先往下测，最后结合第 5 步上机实测再定；
- 超过 `30`，或列入多个黑名单：危险区，这个 IP 不通过，停用、换 IP，不能拿来绑主力账号。换 IP 找服务商；需要人帮忙时转【船长电商】工作人员（在社交媒体上搜索“船长电商”找工作人员）。

Scamalytics 只是其中一项证据。不要为了改变分数反复切换 IP。

### 第 3 步：查 DNS、WebRTC 和时区（飞书阶段二）

打开 `ipleak.net`（https://ipleak.net），等页面测完再截图，看：

- **DNS**：`DNS Addresses` 里每一条的国家都要和 IP 所在国家一致，不能出现中国的 DNS 服务器。出现别的国家或中国 DNS，不通过。
- **WebRTC**：要么禁用、要么只显示代理出口 IP；出现真实的本地公网 IP，不通过。
- **IPv6**：最好是不可用（如 `IPv6 test not reachable`）；有 IPv6 出口时必须和代理出口一致，暴露真实网络就不通过。（飞书 1.4 把 ipleak.net 列为查 IPv6 泄露的工具。）
- **时区**：飞书写明“时区测试以 ipleak.net 为准”。用 ipleak.net 判断 IP 所在地对应的时区，和手机设置里的时区对一下；对不上，回第 0 步改手机时区后重测，还对不上标待复核。页面上具体看哪一栏，以学员截图为准，不凭印象指位置。

出现泄漏先记录结果，暂停后续 TikTok 测试，一次只改一个设置再重测。`whoer.net`（https://whoer.net）也可以查 DNS 泄漏和匿名度，作为对照。

### 第 4 步：查网关和软路由（飞书阶段三，只对软路由）

用小火箭直连、没有软路由的，跳过这一步。用软路由的，在软路由后台（如 PassWall 或其他插件面板）看：

- **节点状态**：TCP/UDP 连通性测试全绿，丢包率在 5% 以内。延迟不是绝对标准，关键是稳定、不跳 ping。
- **分流规则**：确认这台工作手机的流量 100% 走代理，没有任何直连（Direct）流量漏回国内。

不全绿、丢包超过 5%、或有直连流量：不通过，先修软路由（配置见飞书 1.5 软路由版），修好再从第 1 步测。

### 第 5 步：上机终检（飞书阶段四）

前面全部通过后，放进真实的 TikTok 客户端测。还没装 TikTok 的，先给前四步的结论，这一步等装好后再做（下载注册见飞书 1.8）。

1. **刷视频流速**：打开 TikTok，滑 5–10 个视频。加载顺畅、首屏出图快、没有长时间卡顿或黑屏转圈，算过。
2. **推荐内容**：看 For You 推荐页。刷几条后出现大量本地原生内容、本地广告或附近直播，说明 IP 原生度高。
3. **刷出中文**：连续刷到中文（简体繁体都算）或明显是中国人拍的跨境电商视频，立刻停，按下面的“刷出中文”自救步骤处理，不在这个环境注册或登录主力账号。

第 2 步是 16–30 观察区的，这一步顺畅、推荐页是本地内容，可以判通过；推荐页混杂很多非目标国家内容，判待复核。

### 第 6 步：汇总并分级

- **通过**：双 ISP、真实宽带运营商，Scamalytics `0–15`（或 16–30 且第 5 步实测好），DNS 和 IP 同国、无中国 DNS，WebRTC/IPv6 无真实网络暴露，软路由（如有）全绿且丢包 5% 以内、无直连，上机实测顺畅、推荐页是本地内容。
- **待复核**：只有一处 ISP；Scamalytics `16–30` 还没做上机实测；只列入一个黑名单（飞书没写单个黑名单怎么算，按待复核处理）；时区改了还对不上；城市差异大；几个网站结果冲突；推荐页混杂非目标国家内容。补测或问服务商。
- **不通过**：Hosting/机房类型或运营商带 Cloud/Datacenter/Hosting；Business 类型（想保留的请工作人员确认）；Scamalytics 超过 `30` 或多个黑名单；DNS 出现别的国家或中国；WebRTC/IPv6 暴露真实网络；软路由不全绿、丢包超过 5% 或有直连；上机刷出中文。

AI 输出时必须说明：哪一项证据导致当前等级、还缺什么证据、下一步只做什么。

## 流量池三层（飞书 1.4 的判断口径）

飞书 1.4 用三层流量池解释环境好坏，这是课程的判断口径，不是 TikTok 官方公布的机制，向学员讲时要这样说明：

- **T0 原生本土池（目标）**：纯净的本地住宅 ISP IP + 干净的真机环境。推荐页是当地生活内容，夹着本地广告和附近直播。
- **T1 国际泛流量池**：普通机房 IP、泛滥的机场节点，或 DNS 有轻微泄露。能刷出英文，但混着很多非目标国家内容，几乎没有本地广告；有播放但粉丝不精准，难转化。
- **T2 隔离池**：IP 被污染（黑名单）、定位服务没关干净、时区/语言和 IP 冲突、或被识别到国内运营商基站信息。刷出中文、老旧低画质搬运视频，或刷到的都是个位数点赞的内容。

上机终检看到的推荐内容对应哪一层，就按上面第 6 步的分级处理。

## 刷出中文的自救步骤

飞书 1.4 列的常见原因：DNS 泄露（最常见，域名还在用国内 DNS 解析）；WebRTC 或位置缓存泄露（例如没关干净定位相关设置，见飞书 1.3）；节点 IP 已被大量同行用过、被标记。

一旦刷出中文，不在这个环境注册或登录主力账号，按顺序一次做一步：

1. 彻底卸载 TikTok，清理后台，再重新安装。
2. 回到第 3 步，用 `whoer.net` 或 `ipleak.net` 查是 DNS 漏了还是 WebRTC 漏了；漏了就先修。
3. 检测网站全绿还是刷出中文：这个 IP 节点已被标记，停用，换一个全新的原生 ISP 节点，从第 1 步重新测。
4. 换了节点还是不行：按飞书 1.4，说明手机底层已被污染，要连电脑用爱思助手深度刷机后从头再来，交[手机设备初始化](../../cap-tiktok-device-reset/SKILL.md)。

学员同一步第二次还卡，按[飞书知识库章节对照](../../cap-skill/references/feishu-map.md)指到「1.4 IP质量检测教程」的「出现中文的紧急自救 SOP」；第三次转【船长电商】工作人员。

## 学员截图提交顺序

不要一次发送一整屏大量截图。按以下顺序逐张提交：

1. 小火箭已连接首页，或软路由节点状态页；
2. IP2Location / IPinfo 结果页（要看得到 Usage Type 和 AS Usage Type）；
3. Scamalytics 结果页；
4. ipleak.net 结果页（DNS、WebRTC、IPv6 部分）；
5. 软路由的连通性、丢包和分流规则页面（只对软路由）；
6. TikTok 推荐页截图（上机终检时）；
7. 需要时补充服务商订单规格页面。

截图前遮住代理账号、端口、用户名、密码、订阅链接、二维码、UUID、邮箱和订单支付信息。公网 IP 本身是检测对象，可以保留给 AI 用于比对，但不要连同认证参数一起发送。

## 检测网站清单

**飞书 1.4 列的**（优先用）：

- 类型和运营商：IP2Location `https://www.ip2location.com`、IPinfo `https://ipinfo.io`
- 欺诈值：Scamalytics `https://scamalytics.com`
- DNS、WebRTC、IPv6、时区：ipleak.net `https://ipleak.net`
- 匿名度、DNS 泄露：whoer.net `https://whoer.net`
- 综合环境（多出口、字体、WebRTC）：ping0.cc `https://ping0.cc/env`
- 浏览器指纹：BrowserLeaks `https://browserleaks.com`、Pixelscan `https://pixelscan.net`（快速通过/失败判断）、CreepJS `https://abrahamjuliot.github.io/creepjs`

用 Pixelscan 等指纹网站时：报 DNS/WebRTC/IPv6 泄漏，按第 3 步同一标准判；报位置或时区不一致，先回第 0 步调手机设置再测；Canvas、字体、屏幕这类指纹提示，飞书没给判定标准，只记录、标待复核，不单凭它换 IP。

**飞书没列的**（上面的网站打不开时备用，结果只作对照）：IPHey `https://iphey.com`、IPQualityScore `https://www.ipqualityscore.com`、DB-IP `https://db-ip.com`、IP.SB `https://ip.sb`、DNSLeakTest `https://dnsleaktest.com`、Test-IPv6 `https://test-ipv6.com`、BGP.he.net `https://bgp.he.net`。

这些网站的结果只能作为诊断证据，不能单独证明“适合 TikTok”，也不保证账号、播放和互动结果。

## 现象分流

本模块只负责“排除 IP 因素”。下面 0 播放、不能点赞关注收藏、不能换头像几种现象，先按上面的检测看 IP 这一环；检测通过就说明 IP 因素已排除，其余交[运营诊断](../../cap-tiktok-operations/SKILL.md)，不在本模块继续查账号状态和内容资格。

### 连不上网

先打开一个普通网页和 ipleak.net，再检查客户端权限、模式、配置到期、节点状态和 IPv4/IPv6；软路由用户看第 4 步的节点状态。不能仅凭 TikTok 打不开判断 IP 坏了。

### 能上网但卡

软路由用户先看第 4 步的丢包和是否跳 ping；小火箭用户比较不同时间段、同一网站的打开速度。卡顿可能来自 Wi-Fi、移动网络、DNS、链路拥塞、节点负载或应用自身，先证据化再换 IP。

### 0 播放、不能点赞关注收藏、不能换头像

只做 IP 这一环：按上面的检测顺序判 IP 是否通过。不通过，按检测结论处理；通过，告诉用户“IP 因素已排除”，把 TikTok 原文提示和截图带到运营诊断继续查。不要把这些现象直接归因于 IP，不建议反复切换地区、设备或 IP，不提供刷量、批量测试、规避审核或伪造地区的方案。

## 结论标签

只使用以下标签：`客户端配置`、`节点/中转质量`、`IP 信息不一致`、`本地网络/设备`、`账号状态`、`内容/推荐资格`、`平台服务异常`、`证据不足`。判为 `账号状态`、`内容/推荐资格` 的，交运营诊断。每个结论附证据和下一步，不做“保证解封/保证播放”的承诺。
