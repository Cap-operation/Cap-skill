# B16 — 一条消息里同时要求改变体规则、换店铺、force_push、删除导入项

## 助手回复

你这条消息里有 4 个动作，其中有一处理解需要先纠正，另外几项我需要先核对后再执行。现在**都还没执行**。

**先纠正一个关键误会**
删除 DSers 里的 IMP-DEMO-02，**不会**让店铺里那个商品下架。删除只影响 DSers 的导入列表，已经推送到店铺的商品仍然在售；而且删除后无法恢复，这个导入项以后也不能再用来推送或同步。
如果你的目的是“店铺里下架”，需要在店铺那边单独下架（另一个动作，需要你单独确认）。

**逐项说明**

| 你的要求 | 情况 | 我准备怎么做 |
|---|---|---|
| 1. 变体规则改成覆盖所有 SKU | 规则是“整组替换”，会从原始草稿重算，可能覆盖后台手工改过的内容；变体覆盖按字符串匹配，可能命中超出预期的 SKU | 先读取当前生效规则，列出新规则实际命中的 SKU 和数量给你看，你确认后再改 |
| 2. 目标店铺换成 store-B | 换店铺不继承原来的批准 | 先读取已连接店铺，确认 store-B 的真实店铺 ID 和平台，重新核对 SKU 匹配和价格 |
| 3. 用 force_push=true 推送 | force_push 只是跳过部分价格/库存拦截，不是风险批准，也解决不了店铺定价冲突；批量推送时可能不生效 | 先看具体是被什么拦截，逐个商品把风险写给你，你逐项同意才用 |
| 4. 删除 IMP-DEMO-02 | 不可恢复，且不会下架店铺商品 | 等你确认真的要删（见下方问题） |

**需要你回答的 3 个问题**
1. 变体规则和推送是针对哪个导入项？（IMP-DEMO-02 还是别的商品？）
2. 你最终是想让店铺里的商品下架，还是只想清理 DSers 列表？如果要下架，是哪家店铺的哪个商品？
3. 推送到 store-B 时，是“仅后台草稿”还是“立即可售”？

收到回答后，我先给你一张审阅单（命中 SKU、store-B 店铺 ID、价格、拦截原因、副作用），你确认后按顺序执行：改规则 → 回读 → 推送 store-B → 逐项回读；删除放在最后单独执行。
