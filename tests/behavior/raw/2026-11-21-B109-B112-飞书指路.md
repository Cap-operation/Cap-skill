# 规则本身的漏洞或前后矛盾

1. **9.3 与对照表对“非学员”的说法不在同一处**：9.3 写“第二次还卡……按对照表附上飞书”，SKILL.md 边界段写“告诉学员……”，只有 feishu-map.md 的“怎么说”里才有“对方说不是学员就不发链接”。B112 靠读到对照表才不发。建议在 9.3 那句里加一句“对方说过不是学员的，不附飞书”，免得只读 9.3 的模块直接发链接。
2. **“打不开找工作人员”和“第三次才转人工”有轻微冲突**：对照表允许学员说打不开时就请他联系工作人员，但那时还没到第三次。B109 用例标准写“不转人工”。建议在对照表里写清：这是打不开飞书的出口，不算第三次，也不改变卡住次数。我这次的回复把这句括号放在学员版里，评审时容易被当作转人工。
3. **“说不是学员”之后未说明是否永久有效**：用户之后又说“我其实是学员”怎么办、非学员是否还能问课程内容（SKILL.md 第 32 行路由“学员问一转课程内容”），都没写。
4. **B110 的“看不懂”触发条件**：对照表要求“同一个说法讲了一遍还不懂”，而 B110 是第一轮对话就带着“看不懂你说的”，实际上没有前一遍；用例按“已讲过一遍”处理才成立。建议在用例里写明前提。
5. **Apple ID 模块没有“礼品卡兑换失败”的具体排查清单**（SKILL.md 只有一行流程，礼品卡只在步骤链里出现），B112 的诊断只能靠 9.3 的通用顺序，容易凭印象编设置路径。建议在 Apple ID 模块补“画面上找什么”，或在 B112 的判定里加上“不编界面”。
6. 对照表第 1 章“美区 Apple ID 注册资料 / 礼品卡”本来有对应段（1.6 四、消费激活与应用购买），非学员看不到；对非学员和付费内容的边界，对照表没有说有没有替代渠道，只剩“继续诊断”。
