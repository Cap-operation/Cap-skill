# B25 — 外部 Bot 运行中：人工接管、重复事件、自身消息回环、LLM 超时与额度不足

## 助手回复（给商家/运维）

这一批事件我这样处理，同时说明 Bot 现在的真实状态。

**逐个事件的处理**

| 事件 | 处理 | 结果 |
|---|---|---|
| C-77 买家入站消息（第 1 次投递） | 回复前先读会话状态：已由人工接管 | 不自动回复，不调用模型 |
| 同一条入站消息（第 2 次投递） | 按事件/消息 ID 判定为重复 | 丢弃，不处理 |
| Bot 自己发出的 outgoing 消息事件 | 只响应买家入站，忽略自身 outgoing、私密备注和状态事件 | 忽略，避免自己回复自己 |
| 模型调用超时 1 次，且额度不足 | 不循环重试；把会话转人工 | 未发送 AI 回复，已转人工 |

- C-77 由人工负责，自动回复对它保持静默，交回自动处理需要人工在后台明确操作。
- 超时的那个会话：先查过会话里没有已发出的 Bot 消息，再转人工，避免重复回复。交接附问题摘要、已答内容、“模型超时+额度不足”原因。如果超时发生在 C-77 上，说明“回复前先查人工接管状态”这一步没生效，要查 Bot 代码。
- 额度不足期间，新消息都应直接转人工或只出草稿，并请你补额度或调低自动范围；有人值班的队列要能接住。

**关于“外部 Bot 正在运行”**

我这个技能包里没有外部 Bot 的代码，你说的 Bot 是自建服务。今天这批事件里它在去重、忽略自身消息、人工接管、超时回退几项上表现符合要求，但要称为“已实现、可上线”，下面每项都要在测试环境里有记录：

1. Webhook 签名和时间戳校验，拒绝过期或重放事件 — 待验证
2. 去重（含没有事件 ID 时的备用去重键） — 本次部分观察到
3. 只处理指定账户/Inbox，品牌之间知识和凭据隔离 — 待验证
4. 忽略自身 outgoing、私密备注、状态事件 — 本次观察到
5. 每次回复前读最新状态，人工接管即停 — 本次观察到（C-77）
6. 模型/工具超时与额度不足时转人工、发送重试前先查是否已发 — 本次观察到一次
7. 退款、取消、改地址等写动作不由 Bot 执行 — 待验证
8. 日志只记事件 ID、消息 ID、决策和送达结果，不记令牌 — 待验证

在 1、3、7、8 补齐验证记录前，我把这个 Bot 的状态标为“运行中，未完成验收”，不说“自动回复已上线”。
